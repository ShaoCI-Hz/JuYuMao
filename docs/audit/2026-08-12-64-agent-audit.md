## 二、HIGH 级问题全量明细

### A. 播放核心（10）

1. `player/PlaybackController.kt:62-76,156-167,200-210` — **无缝模式错误后无法恢复**：`onPlayerError` 后 ExoPlayer 停在 STATE_IDLE，`next()/playAt()` 只 seek+play 不重新 `prepare()`，解码失败/SMB 断流后无缝队列永久卡死。
   → 修复：错误恢复统一走 `exoPlayer.prepare()` 后再 seek/play。
2. `player/PlaybackController.kt:62-94` — **过渡统计错乱**：`onMediaItemTransition` 不同步 `queue.currentIndex` 与 ExoPlayer 索引，无缝自然切歌后统计计旧歌漏新歌，`lastErrorSongId` 防死循环记错歌。
   → 修复：过渡/索引回调中同步 queue（以 ExoPlayer 为唯一真源）。
3. `player/PlaybackController.kt:97-126` — **repeatMode 从未设置**：无缝模式不遵循单曲/列表循环，播完最后一首直接停止；shuffle 只作用于手动切歌，自然过渡完全绕过 shuffle。
   → 修复：无缝模式设置 `exoPlayer.repeatMode` 并监听 transition/ended 由 queue 续播。
4. `player/PlaybackQueue.kt:78` — **shuffle 下 previous 失效**：`previous(repeatMode)` 默认 shuffle=false，PlaybackController 调用也未传 shuffleEnabled，随机模式"上一首"走顺序逻辑，与 next() 不对称。
   → 修复：调用方传 `queue.previous(repeatMode, shuffleEnabled)`。
5. `ui/queue/QueueViewModel.kt:25-33` — **队列快照过期**：仅 init/playAt/clearQueue 时 refresh，播放中队列变化（切歌/换歌单）完全不反映，当前播放高亮错误；交接报告已承认但属真实功能缺陷。
   → 修复：订阅 PlaybackQueue 的 StateFlow 改为响应式。
6. `player/audio/../smb/SmbStreamSource.kt:17-31` — **忽略 dataSpec.position（seek 失效）**：ExoPlayer seek/恢复播放重新 open 时一律从头读，拖进度条后播放位置错乱。
   → 修复：`open()` 按 position 对输入流 `skip()` 或按 offset 打开。
7. `player/SmbMediaSource.kt:21-23` — **同 seek 缺陷**：工厂创建的流源完全忽略 position（与上一条同根因）。
   → 修复：同上，并给 `SmbClient.openFile` 增加 offset 参数。
8. `player/DynamicLoadControl.kt:45-50` — **短歌曲永远不开始播放**：`shouldStartPlayback` 用固定缓冲门槛且不比较媒体总时长，短于门槛的歌曲永远返回 false，卡死 STATE_BUFFERING。
   → 修复：`bufferedDurationUs < requiredUs && bufferedDurationUs < durationUs` 才返回 false。
9. `ui/player/PlayerViewModel.kt:93,100` — **lastPlayedAt 被覆盖**：先写 now 又被 `extractAndUpdateSong` 基于旧 song 的 update 覆盖回旧值，"最近播放"排序失效。
   → 修复：删除前置写入，统一在最终 update 时写。
10. `ui/player/PlayerViewModel.kt:87-89` — **alreadyPlayingThis 误判**：`PlaybackController.next/previous/playAt` 从不回写 `currentSong`，进入播放页切歌后再点旧歌会误判"正在播放"而跳过，UI 与音频错位。
    → 修复：控制器切歌时同步 `playbackStateHolder.updateSong(...)`。

### B. SMB 网络层（12）

11. `data/remote/smb/SmbClient.kt:144-159` — **openFile 无 offset**：只返回从头开始的流，配合 SmbStreamSource 使 seek 失效（A 组根因链下端）。
    → 修复：openFile 增加 offset 参数或返回后 skip。
12. `data/remote/smb/SmbClient.kt:142-159` — **ioMutex 锁外读取**：返回的 InputStream 在锁外读取，smbj DiskShare 非线程安全，播放流读取期间并发 openFile/list 会请求交错、状态损坏。
    → 修复：返回持锁委托流，或每个读取走专用连接。
13. `data/remote/smb/SmbConnectionPool.kt:50-81` — **池饥饿**：全局 `connectionMutex` 内执行完整 `client.connect()`（最坏 ~45s），一台慢服务器阻塞所有其他 getConnection，Mutex 无超时。
    → 修复：锁内只做快速查找/占位，网络 connect 移到锁外，per-server 锁 + 全局限额。
14. `data/remote/smb/SmbConnectionPool.kt:106-115` — **cleanup 无锁竞态**：`cleanupIdleConnections` 与锁内 getConnection 竞态，可能 disconnect 刚借出的活跃连接，正在播放的流被掐断。
    → 修复：cleanup/evict 全部纳入锁，disconnect 移出 filter 回调。
15. `data/remote/smb/NetworkScanner.kt:39-61` — **prefixLength 未使用**：扫描范围硬编码 1..254 且 baseIp 取前三段，/25、/26 越界、/16 等大子网漏扫，与交接报告"网段探测"声明不符。
    → 修复：用 prefixLength 计算真实网段与主机范围。
16. `data/remote/smb/NetworkScanner.kt:68-102` — **254 并发 TCP connect**：无并发限制，耗尽 socket fd、被路由器判定扫描丢包、大量假阴性。
    → 修复：Semaphore(16..32) 或 limitedParallelism 限流。
17. `data/remote/smb/NetworkScanner.kt:98-100` — **锁外遍历竞态**：`hosts.toList()` 在 Mutex 外，并发 add 可抛 ConcurrentModificationException 使整个扫描失败。
    → 修复：`toList()` 移入 `mutex.withLock`。
18. `data/remote/smb/JcifsShareEnumerator.kt:26,50` — **port 参数未使用**：URL 恒为 `smb://$host/` 走默认 445，139/自定义端口枚举失败。
    → 修复：`if (port != 445) "smb://$host:$port/"`。
19. `data/remote/smb/SmbFileScanner.kt:51-109` — **递归无深度上限/无循环检测**：SMB 符号链接环可致栈溢出或超时，整个扫描失败。
    → 修复：depth 上限 + visited 集合 + 跳过 reparse point。
20. `data/remote/discovery/SmbDiscovery.kt:49-77` — **并发 discover 泄漏 JmDNS**：实例字段被第二次调用覆盖，第一次创建的 JmDNS 永不 close（UDP socket + 后台线程常驻），且 cleanup 会误关对方实例。
    → 修复：Mutex 串行化 discover，listener/jmdns 改为局部变量。
21. `data/remote/smb/SmbClient.kt:128` — **路径拼接未过滤 `..`**：listFiles 的 fileName 直接拼接，恶意/异常服务器可通过 fileName 实现路径遍历。
    → 修复：拒绝含 `..`/`\` 的 fileName 并规范化路径。
22. `data/repository/SmbRepository.kt:44` — **明文密码回写数据库**：`getAllServers()` 返回解密后的明文对象，调用方按自然用法 connect 会把明文密码经 `serverDao.update` 回写，绕过 AES-GCM 加密。
    → 修复：update 前强制 `server.encryptPassword()`，对外只暴露脱敏对象。

## 三、结构性发现（跨文件）

1. **SMB seek 失效链**（#6/#7/#11）：`SmbStreamSource` 忽略 `dataSpec.position` + `SmbClient.openFile` 无 offset → 所有 SMB 歌曲拖动进度条后播放错乱。这是**播放体验最严重的单一问题**。
2. **播放状态双真相源**（#2/#10/#39）：`PlaybackController` 与 `PlaybackStateHolder` 两套状态互不同步，切歌后 UI 落后。建议以 ExoPlayer + PlaybackStateHolder 为唯一真源。
3. **死代码双轨模型**：`domain/model` 的 `Album/PlaybackState/Playlist/SmbServer` 全部零引用，与 Entity 双轨漂移；`LyricsRepository` 零调用、`SmbRepository` 大部分方法死代码、`MusicRepository.insertSong/updateSong/deleteSong` 无调用者、`SongDao.getTodayPlayCount/getAllSongsPaged` 无消费者、`SmbConnectionPool.close()` 无调用者。
4. **设置契约断裂**：`smbAutoConnect`（无 UI 消费）、`smbConnectionTimeout`（死字段）、`playbackSpeed`（UI 不读 DataStore）、`gaplessEnabled/crossfadeMs`（仅 init 读一次，运行中改不生效）——设置页声明了但一半不生效。
5. **凭据安全链**：明文密码风险点 = `ServerEntity.password` 明文落库（#23）+ `SmbRepository` 明文回写（#22）+ `SmbServer.password` 明文内存模型 + `.git/config` remote URL 内嵌 GitHub PAT（本地泄露）+ `CryptoHelper` 解密失败静默返回密文（无前缀区分）。
6. **播放统计失真**：`onMediaItemTransition` 无条件 incrementPlayCount，无 ≥10s 阈值，秒切歌虚增计数（spec T9 验收要求未满足）。
7. **AppViewModel 中文日志编码损坏**：Log 消息为 GBK 乱码（"鑷�姩閲嶈繛"应为"自动重连"），文件需以 UTF-8 重存。
8. **Widget 名不副实**：桌面 Widget 为纯静态占位（固定文案、播放按钮无 clickable、updatePeriodMillis=0 永不刷新），与 README/spec 宣称的"封面+标题+控制"严重不符。
9. **README 声明超卖**：宣称支持 DSD/APE/WavPack，实际 FFmpeg 扩展未引入、这些格式解码失败被跳过。
